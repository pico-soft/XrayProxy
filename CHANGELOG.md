# XrayProxy — История изменений

## v2.24-beta

### Главное

#### Надёжное определение системного VPN
Приложение теперь корректно определяет, идёт ли его трафик через системный VPN, проверяя реальный маршрут (а не просто наличие VPN-интерфейса). Если системный VPN активен, но приложение в него не включено (split-туннель), в логе появляется понятная подсказка — включить приложение в список VPN.

## v2.23-beta

### Главное

#### Подписки добавляются и обновляются надёжнее
Исправлено добавление подписки, когда прямой доступ к ней недоступен: теперь приложение пробует получить серверы через системный VPN, затем через рабочие за последние сутки серверы. Подписка больше не «теряется» при неудаче — остаётся в списке и обновляется автоматически раз в час.

#### Индикаторы статуса подписок
Подписки подсвечиваются: зелёным — успешно обновлённые, красным — не удалось обновить. (В консоли — соответствующая пометка.)

## v2.22-beta

### Главное

#### Стоп-лист работает на лету
Маска из `blacklist.txt` теперь моментально скрывает серверы, в названии которых она встречается, — везде: в списках UI, при ручном выборе, в автовыборе и в мониторе при переключении. Убрали маску — серверы возвращаются обратно без повторного импорта подписок.

Раньше фильтр применялся только в момент импорта (`add_server_manually`, `import_servers_batch`, `parse_subscription_content`). После добавления маски существующие серверы продолжали использоваться монитором и попадать в UI — расхождение между ожиданием «стоп-лист» и реальным поведением.

Модель — **скрытие, не удаление**: серверы остаются в `~/xproxy/servers/*.meta` всегда. Изменилась единая точка чтения — новая функция `get_active_servers(scope, alive_only)` фильтрует blacklist на лету; старые геттеры (`get_servers_by_scope`, `get_alive_servers`) делегируют в неё. Семантика маски не менялась: подстрока в имени сервера, без учёта регистра.

## v2.21-beta

### Главное

#### Честный замер прямого канала и внешнего мира
Раньше `measure_direct_speed` ходила на tele2/OVH и периодически выдавала <0.5 Мбит/с при реальном канале в десятки Мбит/с — `_monitor_loop` принимал это за «слабый интернет» и принимал неверные решения. Теперь замер разведён на два независимых сигнала:

- **Сигнал A — скорость канала**: по близким незаблокированным CDN (mc.yandex.ru, yastatic.net, vk.com). Это и есть «честная» цифра, по которой работает мониторинг.
- **Сигнал B — достижимость внешнего мира**: по хостам вне РФ-whitelist (detectportal.firefox.com, example.com, neverssl.com). Проверяется тело ответа — защита от подмены страницей-заглушкой whitelist-провайдера.

При «канал жив, но внешний мир недоступен» в лог идёт WARNING — это сигнал, что провайдер в whitelist-режиме. Логика автопереключения **не изменена** в этом релизе — на этой итерации только сигналы и логи для калибровки.

Хосты А и B настраиваются через `settings.json` (`channel_speed_probes`, `external_reach_probes`) без правки кода.

#### Cloudflare убран из всех замеров
`test_speed_via_server` и `measure_current_speed` переведены на тот же список A с фолбэком — канал и туннель теперь сопоставимы. Константа `SPEED_TEST_URL` (speed.cloudflare.com) удалена. Cloudflare в проекте под запретом из-за блокировок в РФ.

#### Уборка рантайма
- При старте чистятся остаточные `_test_*` файлы временных тестов (`_run_temp_xray`), которые могли утечь при SIGKILL/reboot во время теста.
- ZIP-логи (`xrayproxy_logs_*.zip`) теперь ротируются: оставляются последние 10 архивов, остальные удаляются. Настраивается через `settings.log_archive_keep`. Сортировка по имени (timestamp в имени = хронологический порядок, устойчиво к touch/copy).

### Обратная совместимость
- Новые ключи `channel_speed_probes`, `external_reach_probes`, `log_archive_keep` в `settings.json` имеют значение `None` по умолчанию — старые `settings.json` без них работают через дефолты.
- `measure_direct_speed` сохранена как обёртка над новой `measure_channel_speed` — обращения из CLI/Web без правок.

### Логирование для калибровки
В `~/xproxy/xrayproxy.log` теперь видно:
- `channel_speed: 27.3 Мбит/с via yastatic (...)` — какой хост A сработал.
- `reach[detectportal]: OK lat=42.1мс` / `reach[example]: FAIL(body)` — статус каждого хоста B отдельно, с причиной провала (timeout / body / net).
- `⚠ whitelist? канал=27.3 Мбит/с | B detectportal=FAIL(body) example=OK neverssl=FAIL(timeout)` — при срабатывании whitelist-детекции.

Это понадобится для подбора более стабильных хостов в следующих версиях по данным с реальных устройств.

### Установка / обновление

Внутри Termux:
```bash
bash ~/xrayproxy/install.sh
```
Или скачайте `xrayproxy.zip` из релиза и распакуйте в `~/xrayproxy/`, затем запустите `install.sh`.
